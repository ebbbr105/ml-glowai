# GlowAI — исследование персонального прогноза тепловых ощущений

> Статус: **исследовательский прототип, не продакшен-модель**. Основа — реальные уличные ответы Pantavou (Афины, 2010–2011). Полевой пилот GlowAI на пользователях в России пока не проводился.

## Задача

До выхода на улицу оценивать субъективное теплоощущение **TSV** (Thermal Sensation Vote): 7 **упорядоченных** категорий от `−3` (очень холодно) до `+3` (очень жарко). Это **не** запрос «хочу теплее/холоднее» (TPV) и **не** доказанная эффективность советов по одежде.

- **M0 — общая модель:** обучается на ответах других людей по погоде и одежде.
- **M1 — адаптация:** сохраняет M0 и корректирует один личный параметр по оценкам **предыдущих дней** пользователя; у нового человека поправка равна нулю.
- **Baselines:** наиболее частая категория, постоянная медиана, модель только по температуре.
- **Компараторы:** XGBoost и CatBoost как обычные 7-классовые классификаторы.
- **Дополнительная диагностика:** радиация, температура шарового термометра и METS носимого устройства. Их нельзя автоматически считать доступными перед выходом.

## Ключевые результаты (среднее по пяти людям)

Для всех моделей — одни и те же 350 **будущих ответов** оставленного участника (leave-one-person-out), качество сначала считается отдельно по человеку.

| Модель | Accuracy, 7 классов ↑ | Ordinal MAE ↓ |
|---|---:|---:|
| Всегда наиболее частый TSV из train | 25.3% | 1.532 |
| Постоянная медиана TSV train | 12.7% | 1.382 |
| Общая порядковая, 4 признака | **51.6%** | **0.620** |
| + личная поправка (λ=10) | 51.1% | 0.627 |
| XGBoost, 4 признака | 50.5% | 0.663 |
| CatBoost, 4 признака | 50.9% | 0.654 |
| Порядковая + радиация/`Tglobe` (диагностика) | **53.8%** | **0.544** |
| + радиация/`Tglobe` + личная поправка | 53.5% | 0.565 |
| Порядковая + METS (диагностика) | 51.8% | 0.628 |

**Объяснение метрик:** Accuracy — точно угаданный TSV, MAE — среднее количество категорий ошибки по **предиктивной медиане**. Accuracy вычисляется по наиболее вероятному классу. Дополнительно приведён RPS для распределения вероятностей, но в презентации основная доступная для объяснения метрика — MAE.

**Вывод:** Общая модель заметно сильнее тривиальных baseline, но устойчивый выигрыш от персонализации **не подтверждён**. Диагностические радиационные признаки связаны с улучшением MAE, однако измерены в момент опроса, а не получены из будущего прогноза погоды. XGBoost не дал выигрыша на этой небольшой выборке.

Важные ограничения: всего **5 независимых участников**, повторные ответы зависят друг от друга; 383 очищенных опроса, три сезона в Афинах, зима только у двух участников. Нельзя обобщать результаты на Москву или заявлять научную доказанность рекомендаций по одежде. См. [подробный аудит](docs/RESEARCH_REPORT.md).

**Быстрая публикация:** [Как залить проект на GitHub](КАК_ЗАЛИТЬ_НА_GITHUB.md). В `slides/` находится актуальная индивидуальная презентация.

## Как воспроизвести

1. Python 3.11+ (локально проверено на Python 3.13).
2. Создать виртуальное окружение, установить зависимости.
3. С сайта авторов скачать `mmc3.xlsx` и `mmc2.xlsx` в `data/raw/` (см. [источник](data/README.md)).
4. Запустить эксперименты:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
PYTHONPATH=src python experiments/benchmark.py --data data/raw/mmc3.xlsx --sensor data/raw/mmc2.xlsx --out results
PYTHONPATH=src python experiments/audit.py --pred results/predictions.csv --out results
python -m pytest -q
```

В Windows PowerShell замените `source .venv/bin/activate` на `.venv\\Scripts\\Activate.ps1`, а `PYTHONPATH=src python ...` на `$env:PYTHONPATH='src'; python ...`. В WSL приведённые команды работают без изменений.

Зачем эти команды: `venv` изолирует библиотеки; `requirements.txt` перечисляет точные семейства пакетов; `PYTHONPATH=src` делает наш модуль `glowai` доступным экспериментам; `benchmark.py` выполняет честный leave-one-person-out; `audit.py` проверяет прогнозы и разбивки; `pytest` запускает проверки метрик и протокола.

Скрипт перезаписывает таблицы в `results/`, поэтому для повторного эксперимента лучше указывать другую папку `--out results_replay/` (и аналогично `audit.py`). Все сравниваемые конфигурации явно записаны в `experiments/benchmark.py`. Их результаты являются **разведочными**, а не результатами заранее зарегистрированного поиска гиперпараметров.

## Структура репозитория

```text
glowai-thermal-ml/
├── src/glowai/          # Загрузка данных, честный split, модели и метрики
├── experiments/         # Benchmark + дополнительная диагностика
├── tests/               # Smoke/regression-тесты
├── results/             # Агрегированные результаты; без первичных анкет
├── docs/                # Научный отчёт, продуктовая интеграция, источники
├── slides/              # Актуальная презентация и PDF
└── data/raw/            # Сюда локально положить mmc2.xlsx и mmc3.xlsx
```

## Что **не** реализовано

Нет доступа к погодному forecast API, расчёта UTCI, Flutter/FastAPI-приложения, хранения оценок пользователей или продакшен-авторизации. Этот репозиторий представляет **ML-исследование**, а не весь код команды GlowAI. Контур приложения — отдельная зона разработчика. Личные оценки в будущем должны поступать через защищённый бэкенд; не следует доверять `user_id` от открытого клиента.
