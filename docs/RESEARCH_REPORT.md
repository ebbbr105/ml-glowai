# GlowAI — аудит DS-исследования, 05.11.2026

## 1. Формальная постановка

Задача — предсказывать **TSV** (Thermal Sensation Vote) — порядковый ответ о тепловых ощущениях на улице, `−3, −2, …, +3`, используя данные условий и одежды. TSV нельзя подменять **TPV** («хотел бы теплее/прохладнее»), показателем комфорта или рекомендацией одежды. На этапе исследования изучается ассоциация между наблюдаемыми условиями и ощущением, а не эффект вмешательства, меняющего одежду.

Основная гипотеза о персонализации: регуляризованная поправка, оцененная на **предыдущих днях** конкретного человека, улучшит будущий прогноз по сравнению с общей моделью. Нулевая гипотеза: улучшение не установлено. Отрицательный результат допустим.

## 2. Источник и очистка

Pantavou, Mavrakis & Nikolopoulos (2017), DOI: https://doi.org/10.1016/j.dib.2017.03.045; данные из приложений `mmc3.xlsx` (анкеты) и `mmc2.xlsx` (датчики).

- Исходных анкет: **391**.
- Исключены **8 записей**, принадлежащих группам с одинаковым участником и временем. Важно: исключаются **все** элементы дублирующейся группы, а не оставляется один произвольный.
- Осталось **383** анкеты, **5** участников, **60** индивидуальных календарных дней (16/15/10/10/9), период июль 2010 — февраль 2011.
- Отложенная проверка на будущих днях: **350** ответов. Первые дни пяти людей (33 ответа) используются только для формирования последующей личной истории.
- Зимние данные присутствуют только у участников 1 и 2. У остальных температура примерно от +17 °C; прямой перенос на московскую зиму не доказан.
- Поля TSV `[-3,+3]`: все 7 классов имеются; частоты полной очищенной выборки `−3:22, −2:18, −1:35, 0:95, +1:47, +2:92, +3:74`. Это **несбалансированная** шкала.

Временные метки привязаны к локальной дате исходных анкет (в файле указан местный сдвиг лета/зимы). Датасет маленький и не содержит независимого внешнего валидационного набора из России.

## 3. Признаки и доступность в продукте

| Группа | Переменные | Использование | Доступность до выхода |
|---|---|---|---|
| T | Температура `Tair` | основные и baseline | потенциально из forecast API |
| W | Относительная влажность `RH`, ветер `WSaver` | основные | потенциально из forecast API; различия измерения/высоты ветра |
| C | Теплоизоляция одежды `Iclo` | основные | если пользователь указал одежду или есть её каталог |
| R | Коротковолновая радиация `SR↓`, температура шарового термометра `Tglobe` | **диагностические** | локально измерялись в момент анкетирования; прямого эквивалента в обычном погодном API нет |
| A | `METS`, данные wearables, синхронизация до 5 минут до анкеты | **диагностические** | наблюдались датчиком во время активности; это не планируемая активность до выхода |

Пропуски в 383 строках: `WSaver` — 1; `METS` — 31 после сопоставления по времени; `Tair/RH/Iclo/SR↓/Tglobe` — 0. Числовые пропуски восполняются **медианой train**, а не по всему датасету; scaling у порядковой модели обучается только на train.

Корреляция TSV с Tair ~0.86, с Tglobe ~0.89, с Iclo ~−0.76; **корреляции не доказывают причинность**. Пользователь выбирал одежду в зависимости от сезона и погоды, поэтому симуляция замены Iclo не равносильна рандомизированному эксперименту по выбору одежды.

## 4. Протокол

Внешнее разбиение **Leave-One-Person-Out**: для каждого из пяти участников общую модель обучаем на **всех остальных четырёх**. Первый день оставленного человека не тестируем, а его более поздние дни оцениваем **последовательно**.

M0 — общая порядковая логистическая модель (`OrderedModel`, 7 упорядоченных классов). M1 — те же фиксированные общие коэффициенты + **один личный сдвиг** с L2-регуляризацией λ=10. При прогнозировании дня D сдвиг оценивается только по меткам **дней, строго раньше D**. Внутри того же дня будущие ответы не подглядываются. XGBoost и CatBoost — обычные multiclass-модели с небольшими деревьями и фиксированными конфигурациями. Замеряется на одинаковом наборе ответов.

**Чего протокол не гарантирует:** глобальная модель использует чужие анкеты, в том числе более поздние календарные даты. Это тест переноса на **нового человека**, не строгий календарный тест всех людей на будущее. Между людьми также есть общая метеообстановка и сезон. Нельзя считать 350 повторных ответов независимыми.

Адаптация человека в режиме replay допускает после дня D использовать уже полученные реальные оценки дня D для следующих дней. Это честный сценарий ежедневного обновления, но не эксперимент с «ровно пятью первыми ответами».

## 5. Критерии

- **Ordinal MAE** (основная для объяснения): среднее абсолютное отклонение между истинным TSV и **предиктивной медианой** вероятностного прогноза, в шагах шкалы.
- **Accuracy-7**: доля случаев, где **мода распределения** (самый вероятный класс) совпала с TSV.
- **RPS**: среднее квадратическое отклонение предсказанных и истинных **накопленных вероятностей** по порогам `−3…+2`; учитывает порядок 7 классов. В таблицах дополнительная вероятностная диагностика, а не единственная метрика защиты.
- **Macro-F1**: равный вес всем семи классам, помогает обнаружить провалы на редко предсказываемых промежуточных категориях.
- **Accuracy-3**: дополнительная продуктовая диагностика групп `холодно (<0) / нейтрально (=0) / тепло (>0)`; вычислена агрегированием вероятностей, **не** обучением отдельной модели.

Каждую метрику считаем по человеку, затем арифметически усредняем пять значений. **Не смешивать** с pooled accuracy по 350 ответам, которая при неравных длинах истории даёт другой результат. Тривиальный baseline выбирает категорию только по распределению **train**, отдельно в каждом внешнем разбиении.

## 6. Основные результаты (перезапуск на исходных двух Excel)

| Эксперимент | Accuracy-7 ↑ | MAE ↓ | RPS ↓ |
|---|---:|---:|---:|
| Самый частый класс | 25.33% | 1.532 | 0.2553 |
| Медианный класс | 12.74% | 1.382 | 0.2304 |
| Термометр `Tair` (ordinal) | 48.93% | 0.658 | 0.0776 |
| `Tair + RH + wind + Iclo` (M0) | **51.58%** | **0.620** | 0.0761 |
| M0 + личный сдвиг (M1, λ=10) | 51.09% | 0.627 | **0.0751** |
| XGBoost, те же 4 признака | 50.47% | 0.663 | 0.0770 |
| CatBoost, те же 4 признака | 50.91% | 0.654 | 0.0764 |
| M0 + `SR↓ + Tglobe` (diagnostic) | **53.75%** | **0.544** | 0.0685 |
| Предыдущая + личный сдвиг | 53.48% | 0.565 | 0.0673 |
| M0 + `METS` (diagnostic) | 51.76% | 0.628 | 0.0767 |

**Интерпретация:** общая порядковая модель заметно сильнее naive baseline, поэтому 51.6% не равнозначно случайному ROC-AUC=0.5. Однако MAE=0.620 не означает готовую рекомендацию одежды. XGBoost и CatBoost на этом протоколе лучше не оказались; это не рейтинг всех возможных их гиперпараметров.

**Радиационные признаки:** улучшение MAE `0.620 → 0.544` (∆=−0.076) и Accuracy `51.6 → 53.8%`; по каждому из 5 участников MAE снизилась. Но результаты имеют статус **exploratory feature ablation / diagnostic**, потому что это непосредственно **наблюдённые во время анкеты** физические условия, а не заранее полученные прогнозные значения. Их использование в реальном приложении потребует отдельной проверки доступности и переноса на прогнозные признаки.

**Активность/METS:** `0.620 → 0.628` по MAE — улучшения не показано. Это не означает, что активность не имеет значения: METS измерялся в другое временное окно, у 31 анкеты недоступен, а активность до выхода неизвестна.

**Персонализация:** M1 против M0 `MAE 0.627 vs 0.620`, `Accuracy 51.1% vs 51.6%`. Выигрыш MAE у 2/5, ухудшение у 3/5. В вероятностной RPS наблюдается небольшой выигрыш M1, **но** по выбранным MAE/Accuracy доказанного эффекта нет. Личная поправка не гарантирует повышения качества; она — проверяемая гипотеза.

## 7. Надёжность и проблемные классы

- Только 5 независимых пользователей. В `results/audit_paired_effects.csv` рассчитаны иллюстративные 95% **bootstrap intervals по пользователям** (10 000 выборок, seed=20261105). Они очень чувствительны к конкретным пяти людям, не дают оснований обобщать на популяцию России.
- Для M1 − M0 по MAE: **+0.0066** категории, приближённый bootstrap-интервал **[−0.0186, +0.0311]**. Интервал включает ноль → преимуществ персонализации не установлено.
- Для радиационной диагностики − M0 по MAE: **−0.0761**, приближённый интервал **[−0.1308, −0.0377]**. Это наблюдаемое улучшение на имеющихся пяти людях, **не подтверждение** применимости прогнозной радиации в России.
- По классам общий M0 точное попадание: TSV `−2`: **0/18**, TSV `+1`: **3/45**. Модель тяготеет к отдельным крупным классам; общая Accuracy маскирует слабое распознавание промежуточных категорий. Macro-F1 ≈ **0.341** при равном весе семи классов.
- При свёртке в три категории `холодно/нейтрально/тепло`: общая M0 **73.6%**, радиационная диагностика **75.7%**. Это вспомогательные метрики, не доказательство качества рекомендаций.

## 8. Проверка утечек и воспроизводимость

Что проверено кодом:

1. Все модели одного сравнения предсказывают **одинаковые 350 пар `(user_id, source_row_id)`** без повторов.
2. Train-фолд не включает тестируемого участника.
3. Personal shift использует `own.local_date < day`, а не текущий или следующий день.
4. Условия, используемые для `SimpleImputer`, `StandardScaler` и параметров модели, обучены только в train-фолде.
5. Хеши исходных `mmc2/mmc3` сохранены в `data/README.md`.
6. Проведены regression/smoke tests; скрипты `benchmark.py` и `audit.py` сохранены для воспроизведения.

Ограничения воспроизводимости: версии библиотек в `requirements.txt` заданы совместимыми диапазонами; XGBoost и CatBoost в других версиях могут давать небольшие различия. Исходные сторонние анкеты в репозитории не переопубликованы; скачать из источника.

## 9. Вывод для НИР и план следующего исследования

**Что выполнено**: очищен реальный outdoor dataset, построен и проверен population baseline, реализована и оценена регуляризованная персональная поправка, воспроизведено сравнение с XGBoost/CatBoost, проверены абляции по физическим признакам, проведена диагностика ошибок и индивидуальных различий.

**Что не доказано**: что персонализация увеличивает точность в России; что контрфактический подбор одежды работает; что TSV является достаточным показателем комфорта; что рекоммендации повышают удержание пользователей; что команда уже провела пользовательский пилот.

**Следующий честный этап:** проектировать пилот ~20 человек × 2–3 недели как **план** (не формальная гарантия мощности), регулярно собирать ID/время/геолокацию с согласия, прогноз погоды **до выхода**, указанную одежду и планируемую активность, а после — реально испытанные условия и TSV. Оценивать общий прогноз и личную поправку на следующих днях; для продукта отдельно проверять связь с TPV/комфортом и успешностью советов по одежде. Если считать MAE и Accuracy для одежды по внешнему погодному API, учитывать forecast-vs-observation shift.
